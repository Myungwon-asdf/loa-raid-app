# LOA RAID

원정대 캐릭터와 주간 레이드 체크를 관리하는 정적 웹 앱입니다. Vercel의 `/api/lostark-sync`가 로스트아크 API를 호출하고 Supabase에 검증된 프로필을 저장합니다.

## 실행 및 검증

- Node.js 24: `node scripts/dev-server.js` (http://localhost:4173)
- 단위 테스트: `node --test tests/*.test.js`
- 안전한 UI 테스트: `node scripts/dev-server.js --fixtures` (http://localhost:4174, `?fail=1`로 실패 상황 확인)
- DB 회귀 테스트: `tests/database.sql`을 트랜잭션 안에서 실행하고 반드시 ROLLBACK합니다.

## 배포

GitHub main 변경은 연결된 Vercel 프로젝트 loa-raid-app에 배포됩니다. 서버 환경 변수 `LOSTARK_API_KEY`가 필요합니다. `config.js`는 브라우저용 공개 Supabase 설정이며 서버 비밀 키를 넣지 않습니다. 빌드는 공개 화면 파일만 public 폴더로 복사합니다.

Supabase 변경 이력은 `supabase/migrations`에 있습니다. 기존 운영 DB에 적용된 이력과 버전을 맞췄습니다. 신규 DB에는 기존 characters/raid_master 스키마를 먼저 준비해야 합니다.

## 동기화 및 주간 기록

- 레이드 체크는 DB 함수에서 해당 캐릭터를 잠그고 변경합니다. 저장 성공 후 화면에 반영하며 실패 시 기존 체크를 유지합니다.
- 실시간 변경, 재접속, 탭 복귀 시 다시 조회합니다. 활성 탭은 60초마다 DB를 확인합니다.
- 주간 기준은 한국 시간 수요일 06:00입니다. 다음 대시보드 조회에서 지난주를 보관하고 새 주차로 전환합니다. 별도 예약 작업은 없습니다.
- 지난주 기록은 화면에서 읽기 전용입니다. 도입 이전의 주차는 복원하지 않으며 도입 시점 데이터를 첫 기준으로 보관합니다.
- 로스트아크 정보 갱신은 사용자가 실행합니다. 전체 갱신은 순차 처리하고 최근 1시간 데이터를 재사용합니다. 개별 갱신은 최근 1분 데이터를 재사용합니다. 마지막 저장 시각과 실패 재시도를 표시합니다.
- 외부 API 요청 중복 억제와 미리보기 캐시는 서버 인스턴스 단위입니다. 전역 사용량 제한 기능은 아닙니다.

## 접근 권한

요청에 따라 기존 로그인 없는 공동 편집 방식을 유지합니다. Discord 로그인과 편집 권한 분리는 포함하지 않았습니다. 공개 키로 기존 데이터 수정이 가능한 구조이며 화면의 읽기 전용 표시는 접근 제어를 대신하지 않습니다.
